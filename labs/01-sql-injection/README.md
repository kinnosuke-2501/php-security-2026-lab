# 01. SQLインジェクション

## これは何？
ユーザーの入力値が、プログラムの組み立てる **SQL文の一部** として解釈されてしまう脆弱性です。
攻撃者は入力欄に「SQLの命令」を書き込むことで、パスワードを知らなくてもログインしたり、
本来見えないデータを盗み出したりできます。

## なぜ起きる？
脆弱版 `vulnerable.php` では、入力をそのまま文字列連結でSQLに埋め込んでいます。

```php
$sql = "SELECT ... WHERE username = '$user' AND password = '$pass'";
```

ここに `$user` として `' OR '1'='1` のような文字列を入れると、条件が常に真になり、
認証チェックが意味をなくします。

## 対策
- **プリペアドステートメント（プレースホルダ）を使う**（`patched.php` 参照）。
  入力は常に「ただの値」として扱われ、命令として解釈されません。
- 入力値のバリデーション（想定する形式かチェック）も併用する。
- DBユーザーの権限を最小限にする（多層防御）。

## 試し方
1. `http://localhost:8080/labs/01-sql-injection/vulnerable.php` を開く
2. `exploit.md` の入力を試して、突破できることを確認
3. `patched.php` で同じ入力を試し、突破できないことを確認
