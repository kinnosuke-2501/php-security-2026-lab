# 01. Webセキュリティの基礎

## 脆弱性とは？
プログラムの「想定外の使われ方」をされたときに、本来できないはずのこと
（他人のデータを見る、管理者になる、サーバーで命令を実行する等）ができてしまう欠陥です。

## ほとんどの脆弱性に共通する原因
> **「データ」と「命令」の境界が崩れること**

| 脆弱性 | 入力が紛れ込む先 | 基本の対策 |
|--------|----------------|-----------|
| SQLインジェクション | SQL文 | プリペアドステートメント |
| XSS | HTML/JavaScript | 出力時エスケープ |
| コマンドインジェクション | OSコマンド | コマンドを使わない / 引数エスケープ |
| パストラバーサル | ファイルパス | パスの正規化と許可リスト |

## 守りの基本原則
1. **入力を信用しない** — フォーム、URL、Cookie、ヘッダはすべて攻撃者が書き換えられる
2. **出力する場所に合わせてエスケープする** — HTMLならHTML用、SQLならプレースホルダ
3. **最小権限** — DBユーザーやファイル権限は必要最小限に
4. **多層防御** — 1つの対策が破られても次で止める
5. **ソフトウェアを最新に保つ** — PHP本体やライブラリの脆弱性はアップデートで直る（`appendix/` 参照）

## 学習の進め方（各ラボ共通）
1. `README.md` で仕組みを読む
2. `vulnerable.php` のコードを読み、どこが危ないか考える
3. `exploit.md` の手順で実際に攻撃してみる
4. `patched.php` と見比べ、何が変わったか確認する
5. 自分で脆弱版を修正してみる（一番力がつきます）
