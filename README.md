# php-security-2026-lab

PHP脆弱性学習用・安全確認用の個人ポケットリポジトリです。

> このリポジトリは、教育目的のみで作成しています。悪用、攻撃、改ざん、外部公開環境での検証を目的としたものではありません。

## 1. リポジトリの目的

このリポジトリの目的は、PHPに潜む脆弱性とその対策を、実際に再現できるPoC（Proof of Concept）として理解することです。

- PHPの脆弱性の仕組みを「なぜ危険なのか」をわかりやすく学ぶ
- 実際の攻撃コードをローカル環境で再現して見る
- 脆弱なコードと、修正後の安全なコードを比較して理解する
- セキュリティの基礎を、初心者向けの説明で学ぶ

本リポジトリは、個人の学習用として扱い、公開サーバーや本番環境での検証は一切行いません。

## 2. このリポジトリで学ぶ内容

本リポジトリでは、PHPのよくある脆弱性を題材に、「どのような入力が危険か」「なぜ攻撃できるのか」「どの対策が有効か」を学びます。

例として扱うテーマは、以下のような観点です。

- 入力値の検証が不足している場合の危険性
- 外部入力をそのまま使うとどうなるか
- コマンド実行やファイル操作に接続しやすいコードの危険性
- ヘッダーやレスポンスの処理で起こりうるインジェクション
- 安全な実装方法と、危険な実装の違い

特に、2026年10月に話題になった大きなPHP脆弱性を題材にすることで、攻撃の発想と修正方法を学ぶことを目指します。

例として、以下のような脆弱性を扱う予定です。

- CVE-2024-4577: PHP CGIの引数インジェクション
- そのほか、PHPに関連する代表的な入力処理・ヘッダー制御・ファイル操作の脆弱性

> これらの脆弱性は、正しくは「実際に悪用されると危険」なものであり、ここでは教育のために安全な隔離環境で学ぶための例として扱います。

## 7. 例として扱う脆弱性の説明

ここでは、PHPの典型的な脆弱性を安全な学習用として扱います。代表例として、以下のようなものがあります。

### 7.1 CVE-2024-4577: PHP CGIの引数インジェクション

これはPHPのCGI実行時に、引数やパラメータが意図しない形で処理されることで、攻撃者がサーバー側の処理を悪用できる問題です。

- 「入力をそのまま渡している」ことが危険
- 予期しないコマンドやパラメータが実行される可能性がある
- その結果、サーバー上で不正な動作が起きる可能性がある

### 7.2 典型的な入力制御の脆弱性

入力値を適切に検証・サニタイズしないと、以下のような危険が出ます。

- コマンド実行の混入
- ファイルの誤読込・誤削除
- HTTPヘッダーの改ざん
- ログインや認可判定の誤作動

### 7.3 なぜ危険なのか

脆弱性があると、悪意のある入力が「本来許可されない処理」を引き起こすことがあります。これはPHPだけでなく、Webアプリケーション全般で重要な問題です。

「入力はユーザーが自由に入れるもの」だと考えると、サニタイズや検証が必要不可欠です。

## 8. どのように再現するか

ここでは簡単な手順で、脆弱なコードと安全なコードを比較します。

### 8.1 脆弱なコードの例

```php
<?php
// 脆弱な例: 入力をそのまま利用する
$page = $_GET['page'] ?? 'home';
include $page . '.php';
```

このコードは、`page` に任意のファイル名を入れられると、意図しないファイルを読み込む可能性があります。

### 8.2 攻撃のイメージ

```text
http://127.0.0.1:8000/?page=../config
```

このような入力があると、想定外のファイルへアクセスする恐れがあります。

### 8.3 重要な前提

- ここでのコードは「教育用の例」であり、実際の攻撃ではありません
- 必ずローカル環境、または隔離されたコンテナ環境でのみ試してください
- 公開済みのサーバーやインターネットに接続した環境では決して使わないでください

## 9. 修正方法の説明

脆弱なコードを修正する際は、まず「入力をそのまま使わない」「許可された値だけを使う」「例外を明示的に処理する」の3つを意識します。

### 9.1 安全な対策の原則

- 入力値をホワイトリストで検証する
- 許可されていない文字やパスを拒否する
- 外部入力をそのままファイル名やコマンドに使わない
- 例外が起きたら安全側に倒して処理する
- 必要ならエラーログを記録しつつ、ユーザーには簡潔なメッセージを出す

### 9.2 修正例

```php
<?php
$allowedPages = ['home', 'about', 'contact'];
$page = $_GET['page'] ?? 'home';

if (!in_array($page, $allowedPages, true)) {
    http_response_code(400);
    echo '不正なページ指定です。';
    exit;
}

include __DIR__ . '/pages/' . $page . '.php';
```

この修正では、許可されたページだけを通し、それ以外の入力は弾くようにしています。これは「入力を制限する」ことが安全性の基本であることを示しています。

## 10. 安全なコードの例

以下は安全なコードの例です。前提として、入力の検証と許可リストの利用が重要です。

```php
<?php
function getSafePage(string $page): string
{
    $allowedPages = ['home', 'about', 'contact'];

    if (!in_array($page, $allowedPages, true)) {
        throw new InvalidArgumentException('Invalid page requested');
    }

    return __DIR__ . '/pages/' . $page . '.php';
}

try {
    $page = $_GET['page'] ?? 'home';
    $path = getSafePage($page);
    include $path;
} catch (InvalidArgumentException $e) {
    http_response_code(400);
    echo '不正なアクセスです。';
}
```

このように書くと、入力が想定外であっても、危険な処理に進まないようにできます。

## 11. 学習の進め方

初心者の方は、次の順番で進めると理解しやすくなります。

1. 脆弱なコードを読む
2. 「どの入力が危険か」を一文で説明する
3. 攻撃の仕組みを図や文章で整理する
4. 安全なコードへどのように修正したかを確認する
5. 似たような脆弱性を自分で探してみる
6. 修正後に、意図した動作と不正な入力への挙動を比較する

学習では、「脆弱性はたまたま起きるものではなく、入力をどう扱うかで起きやすさが変わる」という視点が大事です。

### まず覚えてほしいこと

- すべての入力は信頼できない
- 例外やエラーを見逃さない
- 許可したものだけを使う
- 安全策は「ついでに入れる」のではなく、設計から考える
